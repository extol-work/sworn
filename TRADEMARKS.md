# Trademarks

The SWORN specification is open. The SWORN name is not.

This distinction is deliberate, and it protects you as much as us. An open
specification is only useful if "SWORN" reliably means *this* specification —
the one you can read, implement, and verify against. If anyone could call
anything SWORN, the word would stop telling you what a record is.

## What is licensed

The specification, the reference implementation, and everything else in this
repository are licensed under Apache 2.0. You may implement the specification,
fork it, build products on it, and sell those products, freely and without
asking. Section 6 of the Apache License states that the license does not grant
trademark rights; this document explains what that means in practice.

**"SWORN"** and the SWORN logo are trademarks of Extol, Inc.

## What you can do without asking

- State, accurately, that your software implements the SWORN specification
  (e.g., "implements SWORN v0.1," "SWORN-compatible," "supports SWORN
  attestations").
- Refer to the specification by name in documentation, articles, talks,
  academic papers, and comparisons.
- Use the name in package identifiers whose function is interoperability
  (e.g., a client library named `yourproject-sworn`).

## What requires permission

- Naming your product, service, company, or protocol "SWORN" or a
  confusingly similar variant, or using the name in a way that implies your
  work is authored, endorsed, or certified by Extol when it is not.
- Using the SWORN logo.
- Claiming conformance or certification. A conformance program with a public
  test suite is planned; until it exists, "implements the SWORN
  specification" is the accurate claim, and "SWORN Certified" is not yet a
  claim anyone can make — including us.

## Questions

If you are unsure whether a use is fine, it probably is — but ask:
hello@extol.work. We answer these quickly, and the default answer to
good-faith interoperability uses is yes.
